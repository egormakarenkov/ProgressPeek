# ProgressPeek 0.4.0-beta

A small Windows desktop overlay that estimates progress for the selected task in the observed ChatGPT desktop Codex / Work interface. It retains the latest task while you scroll, uses bounded checks through your signed-in Codex CLI plan, and detects response completion locally. 100% means the response ended normally, not that the wider project succeeded. Experimental ETA uses existing estimates and defaults off.

Windows with .NET Framework 4.x / WPF is required; development verification used Windows 11 and the Framework 4 compiler. The portable ZIP contains one executable and public documentation. The installer installs per user under `%LOCALAPPDATA%\Programs\ProgressPeek`, creates a Start menu shortcut, optionally creates a desktop shortcut, and includes an uninstaller. Close the widget manually before upgrading; setup never forces a process shutdown. Uninstall leaves preferences and usage data under `%LOCALAPPDATA%\ProgressPeek`.

On first launch, read Setup & privacy and explicitly choose whether to enable AI estimates. Cancel leaves estimates blocked; reopen through the widget menu or Settings > Troubleshooting. CLI status checking makes no model request. Install and sign in using the [official CLI README](https://github.com/openai/codex/blob/main/README.md) and [official authentication guide](https://developers.openai.com/codex/auth). No credentials or API keys are bundled, and there is no paid API fallback. CLI, model, plan and entitlement availability can vary.

Legacy TaskProgress preferences and check counts are copied once into the new data folder without deleting originals or copying authentication, transcripts, reports or pending executable updates. Explicit saved ETA preferences survive. Existing destination settings win. Both versions intentionally use the legacy single-instance mutex so a running old version requires closing manually. Unconfigured 0.3 builds cannot discover a new publisher; a one-time manual installation is necessary.

This beta supports only the UI observed during development. Standard chats, browser chats, future layout changes, unsupported accessibility providers, real multi-monitor interactions and a clean machine remain verification limits. Keep the latest response accessible; gaps retain the last estimate. Percentages and ETA are inferred and can revise. Main-task self-reported progress is deferred: it requires explicit prompt/tool integration, and is not necessarily more token-expensive than repeated estimator scans. No exact cost or time comparison is established. See CLEAN-PC.md, PRIVACY.md, SECURITY.md and RELEASE.md.

Build and test locally in Windows PowerShell 5.1: `powershell.exe -NoProfile -File .\build.ps1 -OutputDirectory <new-build-folder>`. Package with `package.ps1 -ExecutablePath <build>\ProgressPeek.exe -OutputDirectory <new-empty-folder> -CompilerPath <official-Inno-7>\ISCC.exe`. The compiler is an external build tool, never packaged. ZIP entries come from exact allowlists. Scripts do not publish.
